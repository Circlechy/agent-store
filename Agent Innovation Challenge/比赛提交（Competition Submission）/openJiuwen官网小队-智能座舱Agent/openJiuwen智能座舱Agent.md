# openJiuwen 智能座舱 Agent

## 【场景介绍】让车内交互回到“自然语言 + 多模态”的真实需求

在真实车内场景中，驾驶与乘坐行为高度动态：上车、通勤、接人、送娃、夜间驾驶、恶劣天气……用户希望系统能“听得懂人话、看得懂画面、记得住偏好”，并在最少打断的情况下完成车控、导航、娱乐与安全相关任务。然而传统车机往往需要多层菜单、固定语句或单一模态输入，导致操作路径复杂、交互割裂、个性化不足。

openJiuwen 智能座舱 Agent 的目标是把“车机交互”从按钮与命令式流程，升级为可理解、可联动、可记忆的智能协作：用户用自然语言提出需求，系统结合视觉、导航、天气、车控与长期记忆，完成解释型的任务链执行。

## 【方案介绍】多模态 + 车控工具链驱动的可执行智能体

### 【问题挑战：为什么传统车机容易“懂意图但做不出来”？】

传统方案常把“理解”与“执行”割裂：语音或文本理解只能输出意图标签，但无法完成跨系统联动；多模态识别结果也难与导航、车控、娱乐统一编排，最终变成“能回答问题、却不能落地动作”的体验。

openJiuwen 采用“工具驱动 + 场景联动”的智能体思路，把车控、导航、天气、音乐、视觉问答等能力统一为可调用工具，使模型不仅能理解，还能执行并解释执行路径。

### 【核心创新：面向座舱的可视化模拟 + 全流程可复现】

我们构建了一个面向智能座舱的多模态模拟器，提供可视化 Web UI、摄像头模拟、乘客识别与长期记忆，让复杂交互在不依赖真实硬件的情况下可复现、可演示、可迭代。该方式降低了车机生态集成成本，同时让功能验证更稳定。

## 【方案设计｜四层协作架构：感知 → 理解 → 规划 → 执行】

1) **感知层**：支持图片/视频输入与摄像头模拟，获取座舱场景与环境信息。  
2) **理解层**：对用户指令、视觉输入与上下文状态进行综合理解。  
3) **规划层**：把复杂需求拆解为可执行的任务链（如“查询天气 → 调节空调 → 播放音乐 → 询问导航”）。  
4) **执行层**：调用车控、导航、音乐、天气、搜索与 TTS 等工具，完成可落地动作与播报。

## 【功能亮点】

- **车控覆盖完整**：空调、车窗、座椅、氛围灯、场景模式一键联动  
- **导航与多途经点**：支持目的地解析、多点规划与到达引导  
- **多模态视觉问答**：识别路牌、停车位、街景并给出行动建议  
- **乘客识别与长期记忆**：主驾/副驾档案、偏好保存与个性化响应  
- **可视化模拟器**：无需真实硬件即可演示、测试、迭代

**场景1：智能上车**
```
用户：小九，我上车了
助手：
1. 自动查询天气
2. 根据温度调整空调
3. 开启座椅通风
4. 播放音乐
5. 询问是否需要导航
```

**场景2：回家模式联动**
```
用户：启动回家模式
助手：
1. 空调设为 24°C 自动模式
2. 氛围灯设为暖色
3. 播放轻松音乐
4. 开启座椅按摩
```

**场景3：视觉问答**
```
用户：[上传路牌图片] 这个指示牌写的什么？
用户：[上传停车位图片] 这个车位能停吗？
```

## 【收益亮点】

- **从“能回答”到“能执行”**：任务链驱动实现跨系统联动  
- **交互自然、路径更短**：自然语言 + 多模态输入降低操作成本  
- **场景可复现、可迭代**：模拟器让功能验证与演示成本更低  
- **个性化体验可持续**：乘客识别与长期记忆提升连续体验

## 【下一步目标】

我们计划在现有能力基础上，扩展车内传感器与行车安全场景的联动能力，形成更加完整的“驾驶辅助 + 乘坐体验”智能协作体系，并进一步开放标准化的工具接口，便于第三方开发与能力扩展。
