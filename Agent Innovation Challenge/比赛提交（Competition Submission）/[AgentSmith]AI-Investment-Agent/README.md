# 投资助手工作流搭建指南

本文档介绍 AI 投资助手工作流的搭建方法和执行流程，帮助用户快速理解和使用工作流编排功能。

## 工作流概览

AI 投资助手工作流是一个完整的股票投资分析决策系统，通过数据采集、信号分析、风险评估和交易决策等多个阶段，为用户提供智能化的投资建议。

### 系统架构

```
用户输入
    │
    ▼
┌─────────────────────────────────────────────────────────┐
│                    数据采集阶段                          │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐              │
│  │股票价格  │  │财务指标  │  │内部交易  │  ...        │

└─────────────────────────────────────────────────────────┘
    │
    ▼

    │
    ▼

│  ┌──────────┐  ┌──────────┐  ┌──────────┐              │
```

## 组件详解

### 1. 输入节点 (Input)

**组件ID**: `input_z4mcf`
**组件类型**: 用户输入 (type=8)

**输入参数**:

| 参数名 | 类型 | 说明 | 默认值 |
|--------|------|------|--------|
| `ticker` | string | 股票代码（如 AAPL） | AAPL |
| `end_date` | string | 结束日期 (YYYY-MM-DD) | 2026-01-15 |
| `start_date` | string | 开始日期 (YYYY-MM-DD) | 2025-10-01 |
| `cash` | number | 可用现金金额 | - |

**配置示例**:
```json
{
  "ticker": "AAPL",
  "start_date": "2025-10-01",
  "end_date": "2026-01-15",
  "cash": 100000
}
```

---

### 2. 数据采集插件组 (Data Collection Plugins)

该阶段使用 5 个 Plugin 组件并行采集多维度数据：

#### 2.1 股票历史价格
**组件ID**: `plugin_g_hkq`
**Plugin**: AI投资助手 / 股票历史价格

**输入**:
- `ticker`: 股票代码
- `start_date`: 开始日期
- `end_date`: 结束日期

**输出**: `data` - 历史价格数据对象

#### 2.2 财务指标
**组件ID**: `plugin_aAnPf`
**Plugin**: AI投资助手 / 财务指标

**输入**:
- `ticker`: 股票代码
- `end_date`: 结束日期

**输出**: `data` - 财务指标数据（PE、PB、ROE等）

#### 2.3 内部交易
**组件ID**: `plugin_gv8Ne`
**Plugin**: AI投资助手 / 内部交易

**输入**:
- `ticker`: 股票代码
- `start_date`: 开始日期
- `end_date`: 结束日期

**输出**: `data` - 内部交易记录

#### 2.4 公司新闻
**组件ID**: `plugin_Tm89K`
**Plugin**: AI投资助手 / 公司新闻

**输入**:
- `ticker`: 股票代码
- `start_date`: 开始日期
- `end_date`: 结束日期

**输出**: `data` - 新闻数据

#### 2.5 股票市值
**组件ID**: `plugin_aO8MI`
**Plugin**: AI投资助手 / 股票市值

**输入**:
- `ticker`: 股票代码
- `end_date`: 结束日期

**输出**: `data` - 市值数据

---

### 3. 数据汇总 (Data Aggregation)

**组件ID**: `text_editor_Zhu4N`
**组件类型**: 文本编辑器 (type=11)
**编辑模式**: StringConcatenation

**功能**: 将 5 个数据源的输出合并为统一格式

**模板**:
```
price:{{prices}}
financial-metrics:{{financial-metrics}}
insider-trades:{{insider-trades}}
news:{{news}}
market-cap:{{market-cap}}
```

**输出**: `output` - 格式化的汇总数据字符串

---

### 4. 信号分析插件组 (Signal Analysis Plugins)

该阶段包含 3 个专业分析师 Plugin，并行分析不同投资策略的信号：

#### 4.1 市场情绪分析师
**组件ID**: `plugin_HHhUB`
**Plugin**: AI投资助手 / 市场情绪-数据分析师

**输入**:
- 汇总数据 (`text_editor_Zhu4N.output`)

**输出**: `data` - 市场情绪分析结果

#### 4.2 增长创新分析师
**组件ID**: `plugin_LkTbX`
**Plugin**: AI投资助手 / 增长创新类-数据分析师

**输入**:
- 汇总数据 (`text_editor_Zhu4N.output`)

**输出**: `data` - 增长创新分析结果

#### 4.3 价值投资分析师
**组件ID**: `plugin_ufT0L`
**Plugin**: AI投资助手 / 价值投资类-数据分析师

**输入**:
- 汇总数据 (`text_editor_Zhu4N.output`)

**输出**: `data` - 价值投资分析结果

---

### 5. LLM 信号解读 (Signal Interpretation)

每个分析师 Plugin 后连接一个 LLM 组件进行深度解读：

#### 5.1 市场情绪解读
**组件ID**: `llm_mBqca`
**模型**: Qwen/Qwen3-32B

**Prompt**: `{{input}}` (直接传递分析师数据)

#### 5.2 增长创新解读
**组件ID**: `llm_sAAZH`
**模型**: Qwen/Qwen3-32B

#### 5.3 价值投资解读
**组件ID**: `llm_KIiOR`
**模型**: Qwen/Qwen3-32B

---

### 6. 信号汇总 (Signal Summary)

**组件ID**: `text_editor_xA5bK`
**组件类型**: 文本编辑器 (type=11)

**功能**: 将 3 个 LLM 的分析信号合并

**模板**:
```
{{signal1}}|{{signal2}}|{{signal3}}
```

**输出**: `output` - 管道符分隔的信号字符串

---

### 7. 风险管理 (Risk Management)

**组件ID**: `plugin_B4agp`
**Plugin**: AI投资助手 / 风险管理-数据分析师

**输入**:
- `ticker`: 股票代码
- `start_date`: 开始日期
- `end_date`: 结束日期
- `cash`: 可用现金

**输出**: `data` - 风险评估结果
- `current_price`: 当前价格
- `remaining_position_limit`: 剩余仓位限制
- `volatility_metrics`: 波动率指标
- `adjustments`: 调整建议

---

### 8. 交易决策 (Trading Decision)

**组件ID**: `plugin_eFJng`
**Plugin**: AI投资助手 / 交易决策-数据分析师

**输入**:
- `ticker`: 股票代码
- `cash`: 可用现金
- `current_price`: 当前价格（来自风险管理）
- `position_limit`: 仓位限制（来自风险管理）
- `signals`: 信号汇总（来自信号汇总）

**输出**: `data` - 交易决策结果

---

### 9. 最终决策分析 (Final Decision Analysis)

**组件ID**: `llm_hEY2M`
**组件类型**: LLM (type=3)
**模型**: Qwen/Qwen3-32B

**功能**: 对交易决策结果进行最终分析和生成投资建议

**输出**: `output` - 最终决策文本

---

### 10. 输出节点 (Output)

**组件ID**: `end_w03W0`
**组件类型**: 结束 (type=2)

**输出参数**: `decision` - 最终决策内容

## 工作流执行流程

### 执行时序

```
时间轴 ─────────────────────────────────────────────────────▶

T0:  start_w03W0 (开始)
     │
T1:  ├─ input_z4mcf (用户输入)
     │
T2:  │  ├─ plugin_g_hkq (股票价格) ────────────────────┐
     │  ├─ plugin_aAnPf (财务指标) ────────────────────┤
     │  ├─ plugin_gv8Ne (内部交易) ────────────────────┤
     │  ├─ plugin_Tm89K (公司新闻) ───── 并行执行 ────┤
     │  └─ plugin_aO8MI (股票市值) ────────────────────┘
     │                      │
T3:                      text_editor_Zhu4N (数据汇总)
     │                      │
T4:                      ├─ plugin_HHhUB (市场情绪) ──┐
     │                      ├─ plugin_LkTbX (增长创新)─┤ 并行
     │                      └─ plugin_ufT0L (价值投资)─┘
     │                               │
T5:                            ┌────┴────┐
     │                            ├─ llm_mBqca ──┐
     │                            ├─ llm_sAAZH ─┤ LLM 并行
     │                            └─ llm_KIiOR ─┘
     │                                 │
T6:                           text_editor_xA5bK (信号汇总)
     │                                 │
T7:                           plugin_B4agp (风险管理)
     │                                 │
T8:                           plugin_eFJng (交易决策)
     │                                 │
T9:                           llm_hEY2M (最终分析)
     │                                 │
T10:                         end_w03W0 (结束)
```

## 配置说明

### Plugin 配置

所有 Plugin 组件都使用相同的 Plugin 源：

**Plugin ID**: `78545269-2c60-433d-9dbb-0ba7f32b31a8`
**Plugin 名称**: AI投资助手
**Plugin 版本**: draft

### LLM 配置

所有 LLM 组件使用统一模型配置：

**模型 ID**: 193
**模型名称**: 1127-2
**模型类型**: Qwen/Qwen3-32B

### 连接关系

工作流共包含 **20 条边** (edges)，定义组件间的数据流向：

1. `start_w03W0` → `input_z4mcf`
2-6. `input_z4mcf` → 5 个数据采集 Plugin (并行)
7-11. 5 个数据采集 Plugin → `text_editor_Zhu4N` (聚合)
12-14. `text_editor_Zhu4N` → 3 个信号分析 Plugin (并行)
15-17. 3 个信号分析 Plugin → 3 个 LLM 组件
18-20. 3 个 LLM 组件 → `text_editor_xA5bK` (聚合)
21. `text_editor_xA5bK` → `plugin_B4agp`
22. `plugin_B4agp` → `plugin_eFJng`
23. `plugin_eFJng` → `llm_hEY2M`
24. `llm_hEY2M` → `end_w03W0`

工作流执行时会输出详细日志，格式如下：

```
DEBUG:common:workflow stream return rsp: {
  'type': 'trace',
  'payload': {
    'id': 'plugin_LkTbX',
    'name': '增长创新类-数据分析师',
    'status': 'start',
    'inputs': {'ticker': 'AAPL', 'end_date': '2026-01-15'},
    'outputs': None,
    'start_time': datetime.datetime(2026, 1, 20, 20, 51, 29, 544664),
    'parent_id': 'text_editor_Zhu4N'
  }

```

### 状态跟踪

每个组件执行时会记录以下状态：

| 状态 | 说明 |
|------|------|
| `start` | 组件开始执行 |
| `running` | 组件正在执行 |
| `finish` | 组件执行完成 |
| `error` | 组件执行出错 |

### Trace ID

每个执行会话有唯一的 `trace_id`，可用于追踪完整的执行链路。

## 扩展指南

### 添加新的数据源

1. 在数据采集阶段添加新的 Plugin 组件
2. 将输入连接到 `input_z4mcf` 的输出参数
3. 将输出连接到 `text_editor_Zhu4N` 的输入

### 添加新的信号策略

1. 在信号分析阶段添加新的 Plugin 组件
2. 将输入连接到 `text_editor_Zhu4N` 的输出
3. 添加对应的 LLM 组件进行解读
4. 更新 `text_editor_xA5bK` 的模板以包含新信号

### 修改 LLM 模型

1. 选择 LLM 组件
2. 在模型配置中更改模型 ID
3. 支持不同模型用于不同分析阶段

## 最佳实践

1. **并行执行**: 数据采集和信号分析阶段使用并行执行提高效率
2. **数据汇总**: 使用文本编辑器组件聚合多个数据源
3. **模块化设计**: 将复杂流程分解为可复用的 Plugin 组件
4. **错误处理**: 每个 Plugin 都有 `error_code` 和 `error_message` 输出
5. **流式输出**: LLM 组件支持流式输出，实时返回分析结果
