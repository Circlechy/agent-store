# openJiuwenCowork

## 项目概述

openJiuwenCowork是一个基于大语言模型的智能自动化助手，通过自然语言指令执行各种文件系统操作。项目采用前后端分离架构，结合 Electron 桌面应用和 OpenJiuwen Agent 框架，实现了智能化的文件管理、目录整理、内容分析等功能。

### 核心价值

- **自然语言交互**：用户无需学习复杂命令，用自然语言描述需求即可完成文件操作
- **智能推理规划**：基于 ReAct 模式的推理-行动循环，自动规划任务执行步骤
- **多场景适配**：支持文件管理、目录整理、内容分析、批量处理等多种应用场景
- **跨平台兼容**：支持 Windows、Linux、Mac 等多平台，正确处理中文路径

## Agent 应用场景
智能自动化助手，通过自然语言指令执行各种文件系统操作，如下办公常用场景：

### 场景一：智能目录整理
**问题描述**：用户拥有大量未分类的文件，需要按照学科、类型、主题等维度进行自动分类整理。

**Agent 能力**：
- 自动分析目录结构，识别文件类型和特征
- 智能识别分类维度（学科、文件类型、项目主题等）
- 自动创建分类文件夹并移动文件
- 生成整理报告

**应用示例**：
```
用户指令："整理下我的目录：openjiuwen-cowork\test\case1-模拟教师界面"

Agent 执行流程：
1. 使用 list_directory 分析目录内容
2. 识别文件特征（数学、物理、语文、英语等学科）
3. 创建分类文件夹（数学、物理、语文、英语等）
4. 使用 move_file 将文件移动到对应文件夹
5. 生成整理报告
```

**技术要点**：
- 文件名精确匹配（禁止修改文件名，确保文件系统标识符准确性）
- 路径处理（正确处理反引号标记，确保路径参数准确性）
- 跨平台路径兼容（Windows/Linux/Mac 路径格式统一处理）

### 场景二：批量文件内容分析与总结

**问题描述**：用户需要分析某个目录下所有文件的内容，并生成结构化的总结文档。

**Agent 能力**：
- 递归读取目录中所有文本文件
- 分析文件内容，提取关键信息
- 生成 Markdown 格式的总结文档

**应用示例**：
```
用户指令："帮我总结下这个文件夹 openjiuwen-cowork\test\case2-模拟笔记，
并在当前目录下生成 markdown 格式文件：总结文档.md"

Agent 执行流程：
1. 使用 read_directory_files 读取目录中所有文本文件
2. 分析文件内容，提取主题、关键词、结构等信息
3. 使用 write_file 生成结构化的 Markdown 总结文档
```

**技术要点**：
- 批量文件读取（支持递归目录遍历）
- 文件大小限制（自动跳过过大文件，避免内存溢出）
- 编码处理（UTF-8 编码，正确处理中文内容）
- Markdown 格式生成（标准格式，无 YAML front matter）

### 场景三：文件内容提取与转换

**问题描述**：用户需要从多个文件中提取特定信息，或进行格式转换。

**Agent 能力**：
- 读取多个文件内容
- 提取关键信息
- 生成新文件或更新现有文件

**应用示例**：
```
用户指令："读取所有 .txt 文件，提取其中的标题和摘要，生成一个汇总文件"

Agent 执行流程：
1. 使用 list_directory 列出所有 .txt 文件
2. 使用 read_file 逐个读取文件内容
3. 提取标题和摘要信息
4. 使用 write_file 生成汇总文件
```

### 场景四：项目结构创建与管理

**问题描述**：用户需要快速创建项目目录结构，或管理现有项目文件。

**Agent 能力**：
- 创建多级目录结构
- 生成项目模板文件
- 管理项目文件组织

**应用示例**：
```
用户指令："创建一个名为 src 的目录，然后在里面创建一个 main.py 文件，
内容为 'print("Hello World")'"

Agent 执行流程：
1. 使用 create_directory 创建 src 目录
2. 使用 write_file 创建 main.py 文件并写入内容
```

## 技术架构方案

### 整体架构

本项目采用 **前后端分离架构**，结合了桌面应用和 AI 能力：

```
┌─────────────────┐    HTTP/SSE    ┌─────────────────┐
│   Electron      │◄─────────────►│   Flask API     │
│   Desktop App   │                │   Server        │
│   - 前端界面     │                │   - Python 后端 │
│   - 文件管理     │                │   - Agent 引擎   │
│   - 实时通信     │                │   - 文件操作     │
└─────────────────┘                └─────────────────┘
                                      │
                                      ▼
                               ┌─────────────────┐
                               │ OpenJiuwen      │
                               │ AI Agent        │
                               │ - 自然语言理解  │
                               │ - 工具执行      │
                               │ - ReAct 推理    │
                               └─────────────────┘
```

### 核心组件
#### 1. **前端 (Electron 桌面应用)**
- **技术栈**: Electron + HTML + CSS + JavaScript
- **功能**:
    - 文件浏览器侧边栏
    - AI 聊天界面
    - 实时执行流显示
    - 工具执行状态跟踪
    - 文件预览功能
- **端口**: 前端通过 HTTP 5001 端口连接后端

#### 2. **后端 (Flask API 服务器)**
- **技术栈**: Python + Flask + OpenJiuwen
- **功能**:
    - 提供 RESTful API 接口
    - 处理 AI Agent 请求
    - 支持流式响应 (SSE)
    - 文件操作代理
- **端口**: 5001
- **主要接口**:
    - `GET /health` - 健康检查
    - `POST /execute` - 执行 AI 查询
    - `POST /stream` - 流式执行 AI 查询
    - `POST /list-directory` - 列出目录内容
    - `POST /read-file` - 读取文件内容

#### 3. **AI Agent (OpenJiuwen 引擎)**
- **框架**: OpenJiuwen ReAct Agent
- **能力**:
    - 理解自然语言指令
    - 自动规划执行步骤
    - 调用文件操作工具
    - 多轮对话推理


## 技术亮点与创新

### 1. ReAct 推理模式

采用 ReAct（Reasoning + Acting）模式，Agent 在执行任务时会：
- **推理（Reasoning）**：分析任务需求，规划执行步骤
- **行动（Acting）**：调用工具执行具体操作
- **观察（Observation）**：获取工具执行结果，调整后续步骤

这种模式使得 Agent 能够处理复杂的多步骤任务，自动规划执行路径。

### 2. 流式执行反馈

使用 Server-Sent Events (SSE) 实现流式响应：
- 实时显示工具执行状态
- 逐步返回 Agent 思考过程
- 提升用户体验，减少等待焦虑

**流式响应格式**：
```json
{
  "type": "tool_start",
  "content": "⚡ Executing tool: read_file",
  "tool_name": "read_file",
  "status": "executing"
}

{
  "type": "tool_completed",
  "content": "✓ Tool 'read_file' executed successfully",
  "tool_name": "read_file",
  "status": "completed"
}

{
  "type": "answer",
  "content": "文件内容：..."
}
```

### 3. 跨平台兼容性

**路径处理**：
- Windows：支持反斜杠和正斜杠
- Linux/Mac：使用正斜杠
- 统一使用 Path 对象，自动处理平台差异

**命令执行**：
- Windows：使用 cmd.exe
- Linux/Mac：使用 /bin/bash
- 自动检测平台，选择合适的 shell

### 4. 错误处理与恢复

**多层错误处理**：
- 工具层：捕获异常，返回友好错误信息
- Agent 层：分析错误，尝试替代方案
- API 层：统一错误格式，返回 HTTP 状态码

**错误恢复机制**：
- 文件不存在：提示用户检查路径
- 权限错误：提示用户检查权限
- 编码错误：跳过无法解码的文件
- 超时错误：提示用户重试或使用更快的模型
