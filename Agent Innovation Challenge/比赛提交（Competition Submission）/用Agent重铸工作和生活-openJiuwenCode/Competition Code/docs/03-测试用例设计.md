## 十、真实用户场景测试 (核心竞争力验证)

> **目标**: 验证 AI 编程助手在真实编程任务中的能力，与 Claude Code 对标

### 10.1 复杂度分级

| 级别 | 描述 | 工具组合 | 预期迭代次数 |
|------|------|---------|-------------|
| L1 简单 | 单文件、单工具 | 1-2 个工具 | 1-3 次 |
| L2 中等 | 多文件、多工具协作 | 3-5 个工具 | 3-8 次 |
| L3 复杂 | 跨模块、需要规划 | 5+ 个工具 + Todo | 8-15 次 |
| L4 高级 | 完整功能开发 | 全工具链 | 15+ 次 |

### 10.2 L1 简单任务 (`test_scenarios_l1.py`)

| 测试用例 | 用户指令 | 预期行为 | 验证点 |
|---------|---------|---------|--------|
| `test_explain_function` | "解释这个函数的作用" | read_file → 分析 → 输出解释 | 正确读取、理解代码逻辑 |
| `test_add_docstring` | "给这个函数添加 docstring" | read_file → edit_file | 生成符合规范的文档字符串 |
| `test_fix_syntax_error` | "修复这个语法错误" | read_file → edit_file | 正确定位并修复错误 |
| `test_rename_variable` | "把变量 x 重命名为 count" | read_file → edit_file (replace_all) | 所有引用都被替换 |
| `test_add_type_hints` | "给这个函数添加类型注解" | read_file → edit_file | 正确推断并添加类型 |
| `test_run_and_explain_error` | "运行这个脚本并解释错误" | bash → 分析输出 | 正确执行、解释错误原因 |

### 10.9 测试执行说明

```python
# 真实场景测试需要 LLM 参与，标记为 slow 和 llm
@pytest.mark.slow
@pytest.mark.llm
@pytest.mark.scenario_l2
async def test_find_and_fix_bug(agent, sample_buggy_project):
    """
    场景: 用户报告一个 bug，要求 Agent 找到并修复

    输入: "calculate_total 函数返回的结果不对，帮我找到并修复这个 bug"

    预期:
    1. Agent 使用 grep 搜索 calculate_total
    2. Agent 使用 read_file 读取相关文件
    3. Agent 分析代码找到 bug（比如 off-by-one 错误）
    4. Agent 使用 edit_file 修复 bug
    5. 可选：Agent 运行测试验证修复
    """
    response = await agent.run("calculate_total 函数返回的结果不对，帮我找到并修复这个 bug")

    # 验证工具调用序列
    assert_tool_called(response, "grep", pattern="calculate_total")
    assert_tool_called(response, "read_file")
    assert_tool_called(response, "edit_file")

    # 验证 bug 确实被修复
    result = run_test(sample_buggy_project, "test_calculate_total")
    assert result.passed
```
