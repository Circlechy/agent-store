## 🔑 关键设计决策

### 1. 为什么选择 ReActAgent？

**理由：**
- ✅ openJiuwen SDK 内置支持
- ✅ 符合 Claude Code 的设计范式
- ✅ 动态推理和工具调用能力强
- ✅ 自我修正机制

**对比其他 Agent 类型：**
- WorkflowAgent：过于死板，不够灵活
- HierarchicalGroup：过于复杂，调试困难

### 2. 为什么采用双模型架构？

**成本分析：**
- 主模型（Sonnet 4）：~$3/1M tokens
- 辅助模型（Haiku 3.5）：~$0.25/1M tokens
- **节省比例：** 70-80%

**使用策略：**
- 主模型（40-50%）：复杂推理、代码生成
- 辅助模型（50-60%）：简单任务、文件读取、分类

### 3. 为什么 LLM 搜索优于 RAG？

**LLM 搜索优势：**
- ✅ 减少系统复杂度
- ✅ LLM 理解代码能力强
- ✅ 可调试、可优化
- ✅ 符合 RLHF 方向

**RAG 劣势：**
- ❌ 引入新的失败模式
- ❌ 相似度函数选择困难
- ❌ 分块策略复杂
- ❌ 两个复杂系统耦合

### 4. 为什么三层上下文架构？

| 层级 | 容量 | 用途 | 持久化 |
|------|------|------|--------|
| 短期 | 100K tokens | 当前会话 | 否 |
| 中期 | 动态 | 压缩摘要 | 会话内 |
| 长期 | 无限 | JIUWEN.md | 跨会话 |

**优势：**
- 平衡内存和效率
- 保留关键信息
- 用户可控

## 📊 技术亮点

### 1. 完整的提示词工程

**总计 12000+ tokens：**
- 系统提示：2800 tokens
- 工具描述：9000 tokens
- 动态提醒：200 tokens

**特点：**
- 大量示例（good/bad）
- IMPORTANT/MUST 标记
- XML Tags 结构化
- 算法化决策流程

### 2. 安全机制

**多层防护：**
1. 命令黑名单
2. 路径限制
3. 危险操作确认
4. 文件大小限制
5. 超时控制

### 3. Sub Agent 隔离

**设计原则：**
- 最多一层分支
- 独立上下文
- 只返回最终结果
- 避免主对话污染

### 4. 工具分层设计

| 层级 | 工具 | 用途 |
|------|------|------|
| 低层 | Read/Write/Bash | 底层操作 |
| 中层 | Edit/Grep/Glob | 常用操作 |
| 高层 | Task/WebFetch | 复杂任务 |
