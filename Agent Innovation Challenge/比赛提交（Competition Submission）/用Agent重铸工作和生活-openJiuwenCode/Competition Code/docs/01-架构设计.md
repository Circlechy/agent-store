## 一、调研总结与核心发现

### 1.1 Claude Code 核心机制

通过对 Claude Code 的逆向工程分析，我们发现了以下八大核心机制：

#### 1. **配额检查 (Quota Query)**
- 使用 **Haiku 3.5** 快速验证 API 配额
- 低成本、高效率的预检查机制

#### 2. **主题检测 (Topic Detection)**
- 判断新话题并生成会话标题
- 使用独立的轻量级提示词

#### 3. **核心 Agent 流程**
- 使用 **Sonnet 4** 驱动主循环
- ReAct（Reasoning + Acting）范式
- 五个核心提示词组件构成系统指令

#### 4. **上下文压缩**
- **92% 阈值**自动触发压缩
- 使用 Sonnet 4 或 Haiku 3.5 生成摘要
- 智能保留关键信息

#### 5. **IDE 集成**
- 通过 **MCP 协议**与 IDE 交互
- 获取代码诊断信息
- 执行代码片段

#### 6. **Todo 短时记忆**
- JSON 文件持久化（`~/.claude/todos/`）
- 实时更新和同步
- 三种状态：pending/in_progress/completed

#### 7. **Sub Agent 系统**
- 隔离环境处理复杂子任务
- 最多一层分支（避免递归）
- 只返回最终结果，不污染主上下文

#### 8. **对话历史总结**
- 使用 **Haiku 3.5** 生成简洁摘要
- 方便用户回顾和管理历史会话

### 1.2 OpenCode 架构洞察

通过分析 [OpenCode](https://github.com/anomalyco/opencode) 项目，我们发现了以下重要的架构设计模式：

#### 1. **多 Agent 模式系统**

OpenCode 引入了三种 Agent 模式，每种模式具有不同的权限和行为：

- **build 模式** - 完全开发权限
  - 可以编辑文件、执行命令、修改系统
  - 用于实际开发工作
  - 所有工具完全可用

- **plan 模式** - 只读分析模式
  - **禁止文件编辑和修改**
  - 禁止执行破坏性命令
  - 用于代码探索、架构分析、任务规划
  - `sed`、文件编辑等工具被禁用

- **review 模式** - 代码审查专用
  - 只读访问代码
  - 专注于代码质量和安全审查

**关键优势：**
- ✅ 用户可以在探索新代码库时使用 plan 模式，避免意外修改
- ✅ 明确的意图分离（规划 vs 执行）
- ✅ Tab 键快速切换模式

#### 2. **客户端/服务器架构**

```
┌─────────────┐         ┌─────────────┐         ┌─────────────┐
│   TUI       │         │   Desktop   │         │    Web      │
│  Client     │         │   Client    │         │   Client    │
└──────┬──────┘         └──────┬──────┘         └──────┬──────┘
       │                       │                       │
       └───────────────────────┼───────────────────────┘
                               │
                    ┌──────────▼──────────┐
                    │   OpenCode Server   │
                    │   (Agent Core)      │
                    └─────────────────────┘
```

**架构优势：**
- ✅ Agent 可以在一台机器上运行，从其他设备远程控制
- ✅ 前后端分离，支持多种客户端
- ✅ 更灵活的部署选项（本地、远程、云端）

#### 3. **提供商无关性**

OpenCode 设计不绑定任何特定的 AI 提供商：

- 支持 Anthropic Claude
- 支持 OpenAI
- 支持 Google Gemini
- 支持本地模型（Ollama 等）
- 通过 Together AI 等聚合服务访问更多模型

**设计理念：**
> "Not coupled to any provider. As models evolve the gaps between them will close and pricing will drop so being provider-agnostic is important."

#### 4. **LSP 开箱集成**

- 原生支持 Language Server Protocol
- 实时代码诊断和错误检测
- 符号跳转和代码导航
- 比传统代码搜索更智能

#### 5. **AGENTS.md 自定义指令**

类似 JIUWEN.md 的项目约定系统：

```markdown
# AGENTS.md

项目特定的 Agent 行为指导：
- 代码风格约定
- 常用命令和脚本
- 测试和部署流程
```

#### 6. **Monorepo + Packages 架构**

```
opencode/
├── packages/
│   ├── cli/          # 命令行客户端
│   ├── desktop/      # 桌面应用
│   ├── server/       # Agent 服务器
│   ├── web/          # Web 客户端
│   └── sdk/          # SDK 和 API
```

**优势：**
- 代码复用（核心逻辑在 server 中）
- 独立的客户端可以并行开发
- 清晰的模块边界

### 1.3 设计哲学（综合 Claude Code + OpenCode）

#### 核心理念：**简单至上 + 灵活扩展**

1. **多模式 Agent 系统**（新增，来自 OpenCode）
   - **build 模式** - 完全权限，用于实际开发
   - **plan 模式** - 只读模式，用于探索和规划
   - **review 模式** - 代码审查专用
   - 模式间可快速切换（Tab 键或命令）
   - 每种模式有独立的工具权限和配置

2. **客户端/服务器分离**（新增，来自 OpenCode）
   - Agent 核心与界面解耦
   - 支持多种客户端（TUI、Desktop、Web）
   - 可远程控制 Agent 运行
   - 更灵活的部署架构

3. **提供商无关性**（新增，来自 OpenCode）
   - 不绑定特定 AI 提供商
   - 支持本地模型和云模型
   - 易于迁移和扩展
   - 模型性能透明化

4. **单一主循环 + 模式约束**
   - 每种模式下保持单一 ReAct 循环
   - 避免多 Agent 复杂性
   - 最大 1 个分支（Sub Agent）
   - 模式级别的工具权限控制

5. **小模型优先 + 智能路由**
   - 50-60% 调用使用小模型（Haiku 3.5 / Qwen3-Coder）
   - 成本降低 70-80%
   - 根据任务复杂度自动选择模型
   - 简单任务（配额检查、主题检测）用小模型
   - 复杂推理（代码生成）用大模型

6. **提示词工程**
   - 2800+ tokens 系统提示
   - 9000+ tokens 工具描述
   - 大量示例和 **IMPORTANT** 标记
   - 模式特定的提示词变体

7. **LLM 搜索 > RAG 搜索**
   - 使用 ripgrep/jq/find 而非向量检索
   - LLM 理解代码能力很强
   - 减少系统复杂度
   - 可选集成 LSP 增强代码理解

8. **Todo 自管理**
   - Agent 维护自己的任务列表
   - 避免上下文偏离目标
   - 利用模型的 interleaved thinking 能力
   - 模式间共享 todo 状态

9. **XML Tags + Markdown**
   - `<system-reminder>` 标签
   - `<good-example>` / `<bad-example>` 对比
   - Markdown 分段结构

10. **双约定系统**（新增，综合两者）
    - **JIUWEN.md** - 项目约定和用户偏好
    - **AGENTS.md** - Agent 行为指导（可选）
    - 自动加载和注入上下文

### 1.4 工具设计原则（综合 Claude Code + OpenCode）

openjiuwen-code 采用三层工具架构（来自 Claude Code），并根据 Agent 模式进行权限控制（来自 OpenCode）：

#### 1. **低层工具**（底层操作）
- `ReadFile` - 读取文件
- `WriteFile` - 写入文件（**build 模式专用**）
- `Bash` - 执行 Shell 命令（权限根据模式变化）

#### 2. **中层工具**（常用操作）
- `EditFile` - 智能编辑（字符串替换，**build 模式专用**）
- `MultiEdit` - 批量编辑（**build 模式专用**）
- `Grep` - 内容搜索（所有模式可用）
- `Glob` - 文件模式匹配（所有模式可用）
- `LS` - 列出目录（所有模式可用）

#### 3. **高层工具**（复杂任务）
- `Task` - Sub Agent 任务
- `WebFetch` - 获取网页
- `WebSearch` - 网络搜索
- `TodoWrite` - 任务管理（所有模式可用）

#### 4. **模式级别的工具权限控制**（新增，来自 OpenCode）

**build 模式（完全权限）：**
- ✅ 所有工具完全可用
- ✅ 文件读写
- ✅ Bash 命令执行
- ✅ 代码修改

**plan 模式（只读权限）：**
- ❌ WriteFile, EditFile, MultiEdit 禁用
- ❌ 破坏性 Bash 命令禁用（rm, mv, mkfs 等）
- ✅ ReadFile, Grep, Glob 可用
- ✅ 只读 Bash 命令（ls, cat, git log 等）
- ✅ WebSearch, WebFetch 可用
- ✅ TodoWrite 可用

**review 模式（代码审查）：**
- ❌ 所有写入工具禁用
- ✅ 只读工具可用
- ✅ LSP 集成增强
- ✅ 代码质量分析

**设计权衡：**
- 使用频率高 → 独立工具（如 Grep/Glob）
- 特殊场景 → 通用 Bash 命令
- 高层抽象 → 确定性工具（如 WebFetch）
- **安全优先** → 模式级别权限控制

### 2.3 核心组件

#### 2.3.1 Agent 类型：**ReActAgent**

**选择理由：**
- ✅ 动态推理和工具调用能力
- ✅ 自我修正机制
- ✅ 灵活的多轮对话
- ✅ 符合 Claude Code 的 ReAct 范式
- ✅ openJiuwen SDK 内置支持

#### 2.3.2 主循环流程

```python
async def main_loop(user_input: str):
    # 1. 配额检查（可选，使用 Haiku）
    await check_quota()

    # 2. 主题检测（可选，使用 Haiku）
    topic = await detect_topic(user_input)

    # 3. 上下文更新
    update_context()

    # 4. ReAct 循环（使用 Sonnet 4 或等效模型）
    for iteration in range(max_iterations):
        # 4.1 构建提示词
        messages = build_messages()

        # 4.2 调用 LLM
        response = await llm.generate(messages)

        # 4.3 判断是否需要工具调用
        if response.tool_calls:
            # 4.4 执行工具
            for tool_call in response.tool_calls:
                result = await execute_tool(tool_call)
                add_tool_result(result)
        else:
            # 4.5 返回结果
            return response.content

        # 4.6 上下文压缩检查
        if context_size > threshold:
            await compress_context()
```

## 三、核心功能设计

### 3.1 Agent 模式系统（新增，来自 OpenCode）

#### 模式类型

**1. build 模式** - 完全开发权限
- **用途：** 实际代码开发、调试、部署
- **权限：** 所有工具完全可用
- **工具：** ReadFile, WriteFile, EditFile, Bash, Grep, Glob, TodoWrite, Task
- **典型场景：**
  - 编写新功能
  - 修复 Bug
  - 重构代码
  - 运行测试

**2. plan 模式** - 只读分析模式
- **用途：** 代码探索、架构分析、任务规划
- **权限：** 禁用所有写入和破坏性操作
- **工具：** ReadFile, Grep, Glob, 只读 Bash, WebSearch, WebFetch, TodoWrite
- **禁用工具：** WriteFile, EditFile, MultiEdit, 破坏性 Bash 命令
- **典型场景：**
  - 探索新代码库

#### 模式感知的工具权限检查

```python
class ModeAwareTool(Tool):
    def __init__(self, mode_manager):
        self.mode_manager = mode_manager

    async def ainvoke(self, inputs: Input, **kwargs) -> Output:
        current_mode = await self.mode_manager.get_current_mode()

        # 检查工具在当前模式下是否可用
        if not self.is_available_in_mode(current_mode):
            raise ModePermissionError(
                f"{self.name} 在 {current_mode} 模式下不可用"
            )

        # 执行工具逻辑
        return await self._execute(inputs)

    def is_available_in_mode(self, mode: str) -> bool:
        """检查工具在指定模式下是否可用"""
        mode_permissions = {
            "build": ["read", "write", "execute"],
            "plan": ["read", "read_only_execute"],
            "review": ["read"]
        }
        return self.required_permission in mode_permissions.get(mode, [])
```

class SubAgent:
    """Sub Agent for isolated task execution"""

    def __init__(self, parent_agent):
        self.parent = parent_agent
        # 隔离的上下文
        self.context = {}
        # 独立的消息历史

### 3.7 Skills 系统

#### 概述

Skills 系统是 openjiuwen-code 的扩展能力框架，与 Claude Code 的 Skills 系统兼容。它允许用户通过 SKILL.md 文件定义可复用的技能，并支持从远程 marketplace 安装第三方插件。

#### 核心组件

```
Skills 系统架构
├── SkillLoader          # 技能加载器
│   ├── 本地 skills (~/.jiuwen/skills/)
│   ├── 项目 skills (.jiuwen/skills/)
│   └── 已安装 skills (~/.jiuwen/plugins/cache/)
├── SkillMatcher         # 技能匹配器
│   └── 根据用户输入匹配最佳 skill
├── SkillExecutor        # 技能执行器
│   └── 执行 skill 并管理工具权限
├── SkillManager         # 技能管理器
│   └── 统一管理 skills 生命周期
└── SkillInstaller       # 远程安装器
    ├── Marketplace 管理
    └── 插件安装/卸载/更新
```

#### SKILL.md 格式

Skills 使用 SKILL.md 文件定义，包含 YAML frontmatter 和 Markdown 内容：

```markdown

name: example-skill
description: 示例技能描述
allowed-tools: Bash,Read,Write
user-invocable: true
---

# Example Skill

这里是技能的详细说明和指导...
```

**Frontmatter 字段**：
- `name` - 技能名称（必需）
- `description` - 技能描述（必需）
- `allowed-tools` - 允许使用的工具列表
- `user-invocable` - 是否可由用户直接调用

#### 三层优先级加载

Skills 从三个位置加载，优先级从高到低：

1. **项目级 Skills** (`.jiuwen/skills/`)
   - 项目特定的技能
   - 优先级最高
   - 来源标记：`PROJECT`

2. **本地 Skills** (`~/.jiuwen/skills/`)
   - 用户自定义的全局技能
   - 中等优先级
   - 来源标记：`LOCAL`

3. **已安装 Skills** (`~/.jiuwen/plugins/cache/`)
   - 从 marketplace 安装的第三方技能
   - 优先级最低
   - 来源标记：`MARKETPLACE`
