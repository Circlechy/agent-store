# 谁是卧底 Agent

## 1. Agent应用场景

### 场景概述

谁是卧底 Agent 是一个基于 React Agent 构建的多角色、多工作流协作游戏系统。系统由一个主持人 Agent 和三个 NPC 工作流组成，共同为用户提供沉浸式、自动化的“谁是卧底”游戏体验。用户以玩家身份加入对局，与 AI 角色同台竞技，实现真实、流畅、趣味十足的社交推理游戏。

### 典型用户场景

1.  **休闲娱乐**：用户想在休息时间玩一局轻松有趣的推理游戏，无需寻找真人队友，随时开局。

2.  **社交破冰**：朋友聚会或线上社群活动中，主持人 Agent 可作为“裁判”，带动气氛，让游戏更公平、更顺畅。

3.  **AI 能力展示**：开发者希望展示多 Agent 协作、工作流调度、自然语言交互等能力，用于技术演示或产品体验。

4.  **游戏化教学**：用于教学场景，让学生在游戏中学习逻辑推理、表达能力与团队协作。

### 核心技术组件

#### 2.1 主持人 Agent（React Agent）

主持人 Agent 是整个游戏的核心协调者，负责游戏流程控制、状态管理与用户交互。

- 自动生成平民词与卧底词

- 随机分配卧底身份

- 按轮次引导发言与投票

- 调用 NPC 工作流获取 AI 行为

- 统计投票、判断胜负

- 游戏结束后进行复盘

主持人通过标准化的 function call 格式与 NPC 工作流通信，确保交互一致、可预测。

#### 2.2 NPC 工作流（多角色协作）

三个独立工作流分别扮演“小鱼儿”“包大人”“孙文”，每个工作流集成意图识别组件，具备以下能力：

- 每个NPC独立人设：每个角色扮演者有自己的独立人设

- 意图识别：精准识别当前核心意图，包含发言意图、投票意图及其他辅助意图（如确认游戏规则、询问当前轮次等）

- 发言响应：根据识别的发言意图，结合自身身份（平民/卧底）与词语，从“使用时长/常见场景/个人故事”中随机选择角度生成描述

- 投票响应：根据识别的投票意图，结合全场发言进行逻辑推理，完成投票操作

- 规则遵守：严格遵守游戏规则（不能投自己、不能投已淘汰玩家），针对其他辅助意图给出合理回应

NPC 工作流的输出内容简洁、自然，与真人玩家无异。

#### 2.3 游戏状态与上下文管理

为确保游戏流程正确执行，系统需要维护完整的游戏状态，配合上下文记忆实现全流程连贯运转，核心管理内容包括：

- 当前轮次与游戏阶段（发言阶段/投票阶段）

- 存活玩家列表与已淘汰玩家记录

- 各玩家的词语、身份及历史行为记录

- 全场历史发言与投票记录

- 游戏结束条件判断标识

通过该组件保障多轮交互中信息不丢失，确保游戏逻辑顺畅推进。
