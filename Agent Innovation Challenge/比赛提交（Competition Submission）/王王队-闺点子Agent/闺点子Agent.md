# 闺点子——基于记忆增强搜索的贴心手机助手

## 项目背景

### 场景概述

在移动端做决策的那一刻，用户真正缺的往往不是“信息”，而是**能把碎片信息变成可执行结论的判断力**：同类商品上百个参数与口碑彼此冲突，想快速筛出“更适合我”的那一款却无从下手；跨平台到手价算不清；临门一脚要下单时，才想起自己有过敏/忌口/健康限制，却来不及逐条核对禁忌与风险；收藏与聊天记录里明明有关键线索，却在需要时怎么也找不到。

**闺点子正是为解决这些痛点而生——它如同最懂你的闺蜜，能够基于对你的深度了解，洞察你内心的真实需求，在关键时刻给出最适合你的建议。**

### 用户决策困境

- **信息碎片化**：相关信息散落在微信聊天、淘宝浏览历史、小红书笔记、便签等各个应用中
- **记忆负担重**：记不清自己的过敏史、饮食禁忌、消费偏好等个人信息
- **决策效率低**：需要在多个平台反复搜索、对比，耗时耗力
- **缺乏个性化**：传统搜索引擎无法理解用户的个人背景和特殊需求

### 核心解决方案

基于 `openJiuwen Core` 构建记忆增强型深度搜索Agent系统，系统聚合用户在各个应用中的历史数据（浏览记录、收藏、点赞、短信、便签等），自动关联用户的偏好、禁忌、健康信息等个人记忆，融合个人历史记忆与实时网络信息，运用多阶段推理引擎，为用户提供个性化推荐和风险预警。

- 🛍️ **购物决策支持**：基于你的消费历史和偏好模式，结合网络种草拔草信息，帮你避开不适合的商品，挑选最符合你习惯的选择
- 🔎 **多平台智能比价**：同款识别 + 到手价拆解（券/满减/配送/会员）+ 可信价格区间，避免"看着便宜、买完变贵"
- 🍽️ **个人健康关怀**：在点餐时自动检测过敏原、忌口和健康限制，提供风险预警和替代建议，守护你的饮食安全
- 💡 **智能洞察**：通过记忆增强搜索，系统能够"记住"你的偏好和限制，在每次决策时都能提供个性化的精准建议

真正做到**懂你所需、选你所爱**。

## 典型应用场景

### 场景一：购物决策支持

**典型用例**：

> 用户在购物平台搜索商品时，左滑唤醒闺点子，系统识别用户意图，主动提供帮助："是不是又不知道该挑哪款面霜啦？"

**场景描述**：在移动购物场景中，用户面临信息过载和选择困难。商品列表琳琅满目，但缺乏有效的筛选机制，用户难以快速做出符合个人偏好的决策。

**系统工作流程**：

1. **内部记忆检索**：
   - 从个人记忆中提取用户的购买历史、浏览偏好、评价反馈等个人数据
   - 搜索用户在淘宝/京东的浏览历史截图
   - 提取用户的肤质记录（如"混合偏干"）
   - 查找用户便签中的护肤偏好（如"敏感肌"）

2. **外部口碑透视**：
   - 结合网络上的种草拔草内容、产品评测、用户口碑等多源信息
   - 在小红书搜索该面霜的真实用户评价
   - 提取关键信息：优点、缺点、适用人群
   - 特别关注"踩雷"和"适合敏感肌"等关键词

3. **智能推理与个性化回答**：
   - 通过多阶段工作流引擎，综合个人偏好、性价比、口碑、使用场景等因素，生成个性化推荐清单
   - 基于历史数据和外部反馈，识别可能不符合用户习惯或存在潜在问题的商品

**输出示例**：
```
- 我猜你想问:
我最近在看这款面霜,适合我吗?

- 根据:
**🎯 你的情况我记得:**
你是**混合偏干、敏感肌**[来源:personal_memory]

**商品评价:**
- **保湿力**: 质地轻盈,适合混合肌[来源:小红书]
- **⚠️ 注意**: 含有酒精成分,敏感肌需谨慎[来源:小红书]

- 回答:
记得你是**敏感肌**哦,这款面霜有酒精成分可能会刺激,建议先买小样试试~
```

### 场景二：多平台商品比价与对比

**典型用例**：

> 用户浏览商品详情页时左滑唤醒闺点子，系统识别用户意图，主动提供帮助："我最近在看这款耳机，哪个平台性价比高，看看各平台到手价与推荐购买方案？"

**场景描述**：同一件商品在不同平台/不同店铺价格差很多，叠券、满减、运费、会员价算不清，最后"买完发现更便宜的"特别扎心。

**系统工作流程**：

1. **内部记忆检索**：
   - 从个人记忆中提取用户的购买历史、价格敏感区间、平台偏好等个人数据
   - 搜索用户在各平台的浏览历史，了解用户常购平台和价格接受范围

2. **外部价格信息采集**：
   - 搜索各平台（京东、淘宝、拼多多等）的同款商品价格信息
   - 统一口径计算"到手价"，拆解券、满减、运费/配送、会员折扣、时间门槛（限时/限量）
   - 采集各平台的店铺类型、售后政策、发货时效等信息

3. **风险权衡与下单建议**：
   - 把"便宜"与"保障"一起算（售后/保修/发货时效/真伪风险）
   - 综合个人偏好、价格、保障等因素，推荐平台 + 推荐店铺类型（自营/旗舰/授权）
   - 标注需要注意的坑（预售、定金、跨店满减不可叠等）

**输出示例**：
```
- 我猜你想问:
我最近在看这款耳机，哪个性价比高，看看各平台到手价与推荐购买方案？

- 根据:
**🔍 同款校验结果:**
✅ 已找到3个平台的同款商品（完全同款）
- 差异点: 京东自营版含1年延保，淘宝旗舰店送收纳包

**💰 到手价对比:**
| 平台 | 标价 | 优惠券 | 满减 | 运费 | 会员折扣 | 到手价 |
|------|------|--------|------|------|----------|--------|
| 京东自营 | ¥899 | -¥50 | -¥30 | 免运费 | -¥20 | ¥799 |
| 淘宝旗舰 | ¥899 | -¥80 | - | ¥10 | - | ¥829 |
| 拼多多 | ¥849 | -¥30 | - | 免运费 | - | ¥819 |

**📊 价格分析:**
- 历史低价: ¥749（去年双11）
- 当前最低: 京东自营 ¥799（含延保）
- 建议: 现在价格适中，京东自营性价比最高（含延保+免运费）

**💡 下单建议:**
推荐在**京东自营**购买，原因：
1. 到手价最低 ¥799，且含1年延保
2. 自营店铺，售后保障更可靠
3. 免运费，无需凑单
⚠️ 注意: 优惠券限时24小时，建议尽快下单
```

### 场景三：个人健康关怀

**典型用例**：

> 用户在购物车页面左滑唤醒闺点子，系统识别用户意图，主动提供帮助："帮我检查一下购物车里的食物有没有需要注意的地方吧"

**场景描述**：用户在点餐应用中完成选餐后，需要快速验证所选食物是否符合个人饮食限制（过敏原、忌口、健康管理需求等），避免误食风险。

**系统工作流程**：

1. **内部记忆检索**：
   - 从历史记忆中提取用户的过敏信息、忌口偏好、饮食限制、健康管理目标等数据
   - 搜索用户健康记录："坚果过敏"
   - 搜索便签记录："不能吃花生"
   - 搜索聊天记录："上次吃花生过敏了"

2. **外部健康信息采集**：
   - 搜索外部知识库（食物成分数据库、过敏原信息、营养数据库等）获取购物车中食物的详细成分信息
   - 分析食物成分，识别可能含有过敏原或不符合饮食限制的食物

3. **主动风险提示与智能建议**：
   - 提供风险提示、替代方案推荐，或给出"可少量食用"等分级建议

**输出示例**：
```
⚠️ 温馨提醒:

- 我注意到:
你正在看的外卖**宫保鸡丁含有花生**[来源:外卖截图]

**🎯 你的小禁忌我记得:**
你之前提到过**对花生过敏**[来源:personal_memory],
上次吃了之后有不良反应[来源:微信聊天]

- 建议:
这道菜不太适合你哦~帮你推荐几个类似口味但不含坚果的菜品吧?
```

### 核心技术组件

#### 2.1 多阶段工作流引擎

基于 `openJiuwen Core` 的工作流编排系统，实现搜索任务的智能分解与执行：

- **入口节点 (StartNode)**: 初始化搜索上下文，接收用户查询
- **意图识别(ImageIntentRecognitionNode)**: 识别用户于当前手机界面的搜索意图
- **问答路由 (SearchEntryNode)**: 判断查询是否需要深度搜索，支持图像和文本两种输入模式
- **规划推理 (SearchPlanReasoningNode)**: 使用LLM进行任务分解，生成多步骤搜索计划
- **信息采集 (SearchTeamNode)**: 执行子工作流，通过ReAct模式循环调用搜索工具
- **答案生成 (SearchAnswerNode)**: 整合多源信息，生成结构化答案
- **结束节点 (SearchEndNode)**: 完成搜索流程，返回最终结果

**技术特点**：
- 支持异步流式执行，实时返回中间结果
- 通过SSE向前端推送推理过程
- 支持并发控制和会话管理

#### 2.2 记忆增强搜索机制

系统核心优势在于**内部记忆的深度挖掘与个性化应用**，通过聚合手机用户散落在各个应用中的碎片化历史数据，构建个人专属记忆库，结合实时网络搜索实现精准决策支持。

**内部记忆的价值**：
- **动态记忆检索**：在搜索过程中，实时从浏览记录、收藏、点赞、短信、便签等多源数据中提取与当前查询相关的个人记忆，包括偏好、禁忌、健康信息等
- **上下文关联**：自动关联用户在不同场景下的历史行为，在搜索过程中动态构建相关记忆片段
- **个性化匹配**：基于检索到的内部记忆，精准匹配用户真实需求，避免"千人一面"的通用建议

**多源信息融合策略**：
- **内部记忆优先**：优先从个人历史记忆和本地知识库检索，确保建议符合用户个人情况
- **外部信息补充**：结合实时网络搜索（种草拔草、产品评测、价格信息、健康知识等）补充最新信息
- **知识优先级**：内部记忆 > 外部网页搜索 > 大模型自身知识，确保个性化建议的准确性
- **上下文感知**：利用SearchContext管理对话历史和搜索状态，支持多轮对话和上下文理解

**工作流程**：
1. **记忆检索**：根据当前查询意图，从内部记忆库中动态检索相关的个人记忆信息（历史偏好、健康限制、消费习惯等）
2. **外部补充**：根据规划结果，调用网络搜索工具补充实时信息
3. **智能融合**：整合检索到的内部记忆与外部信息，按优先级组织知识结构，生成个性化建议
