# 挂号助手智能体 （Registration Assistant Agent）、


## 【场景介绍】帮助患者想找到真正匹配自身病情的医生

随着医学体系持续走向专科细分与亚专科化，诊疗能力不断垂直深化，医生的知识结构与诊疗边界愈发清晰；但与此同时，原本应由医疗系统承担的“分诊与路径决策”成本，正在被显著转嫁给患者——患者想找到真正匹配自身病情的医生，反而变得越来越难。在真实就医中，“多次辗转不同医院、接触多位专家却仍难以定位病因”的情况并不少见，患者往往在信息不对称与路径不确定中反复试错。

以杭州为例，全市分布着上百家医院、上百个科室、上万名擅长不同病情的医生，并且持续涌现“多学科联合门诊”“复合型专科”等新型服务形态；但对普通患者而言，科室与医生介绍普遍专业晦涩、信息割裂，“到底该挂哪个科、找哪位医生”成为就医的第一道门槛，很多患者只能凭经验或直觉选择，挂错号、白跑一趟的现象普遍存在，造成时间成本与治疗窗口的双重损失。[【1】](https://health.gmw.cn/2022-07/20/content_35896617.htm).例如患者出现“右上腹疼痛伴随发烧”，可能误判为感染性问题去挂感染科，最终却发现是胰腺相关疾病，更应就诊消化内科——不得不重新排队、重新挂号，延误就医效率。

挂号助手智能体正是为解决这一“诊前分诊与医生匹配”痛点而生：患者只需用自然语言描述症状，智能体先理解病情表达，再在真实医疗资源中完成检索与匹配。不同于通用大模型只能给出泛化建议（如“去某某科看看”），本项目汇集了杭州 3000+ 医生的真实资料与专长画像，可在跨医院、跨科室的范围内精准推荐更匹配的医生与就诊路径，把“挂号选择”从碰运气的试错升级为可解释、可落地的智能决策，从而显著减少误挂号与无效奔波，提升真实就医效率与体验。


## 【方案介绍】基于渐进式揭露思想的类人服务发现

### 【问题挑战：为什么传统方案在“3000+医生服务发现”上失效？】

在挂号助手里，最难的不是“能不能回答问题”，而是在海量医疗资源中稳定、准确地找到最适合病情的医生。

最直接的做法，是把杭州 3000+ 医生都抽象成“工具/能力卡片”，把他们的简介、擅长、规则一次性塞进提示词，让大模型当场选择——理论上可行，工程上灾难。
因为这会带来典型的 Prompt Bloat（提示词膨胀）：上下文被大量工具/医生描述挤满，模型注意力被稀释，推理质量下降、延迟升高，系统成本与稳定性都不可控。相关研究也明确指出：当工具规模增长时，LLM 会面临“提示词膨胀 + 选择复杂度”的双重压力，难以有效利用大量外部工具。

另一条主流路线是“语义向量检索”：将医生资料与用户病情描述向量化，做 Top-K 相似度召回。这条路在信息检索场景很常见，但在医疗分诊语境里会遇到更隐蔽的瓶颈：
“病人语言 → 医疗服务”并不是简单的语义相似，而是复杂映射。
同一种疼痛可能来自完全不同系统；症状描述常带隐含约束（病程、诱因、伴随症状、危险信号）；很多时候“文本最相似”并不等于“路径最正确”。业界对 RAG 的反思也指出，单靠 embeddings 相似度往往不足以支撑真实业务决策，仍需要更强的结构化建模与推理过程。

### 【核心创新：让 LLM 用“更接近人类”的方式发现服务】

我们最终选择了一条更“人类”的路线：服务发现不应该让模型一次性读完百科全书，而应该像人查资料一样——先选对分类，再翻对目录，最后进入细节。

这正是交互设计中经典的 **渐进式揭露（Progressive Disclosure）**思想：先呈现必要信息与轻量索引，把复杂细节延后到“需要时再展示”，从而降低认知负担、提升决策质量。这一思想也被 Claude Skills 的实践所证明：初始只提供技能的最小元数据（名称/描述），只有当模型决定“要用哪个技能”时，才加载其完整说明，从而有效避免上下文膨胀。

我们的判断是：在医生服务发现问题上，渐进式揭露不是交互技巧，而是一种更适配 LLM 推理机制的检索范式。
它让模型把“强语义理解能力”用在关键决策上，同时把 token 花在真正必要的信息上。

### 【方案设计｜三层分诊架构：一级门诊 → 二级门诊 → 医生匹配】

基于渐进式揭露，我们实现了一套层次化服务发现流程，让模型以近似 O(log N) 的效率在海量医生中完成精准定位：

第一层：一级分诊（大方向定位）
系统先让 LLM 在极少分支内做“方向判断”，例如消化/呼吸/神经/感染/外科等大类。
此时暴露给模型的不是医生全量信息，而是轻量的“目录页”：每个一级门诊只有一句话用途描述，确保 token 成本可控，并充分利用 LLM 对复杂语义关系的理解能力。

第二层：二级分诊（亚专科收敛 + 主动追问补信息）
进入一级门诊后，再揭露该方向下的二级门诊（亚专科/联合门诊/复合专科等）。
同时，系统会根据门诊知识与分诊提示词设计，主动向病人追问关键缺失信息（例如疼痛位置变化、持续时间、伴随发热/呕吐/黄疸等），用最少轮数补齐决策所需线索，进一步减少幻觉与误分诊风险。

第三层：医生匹配（从“正确路径”到“最合适医生”）
当二级门诊确定后，系统才按需揭露该门诊内医生卡片（擅长病种、诊疗方向、可解释标签、排班/号源），并完成“最终推荐”。
最终输出不仅包含“推荐谁”，还包含“为什么是他/她”的解释链条，把挂号从“碰运气”变成可解释、可落地的智能决策。

### 【收益亮点】


- 避免提示词爆炸：信息按需加载，不把 3000+ 医生一次性塞进上下文，显著降低 Prompt Bloat 风险。
- 准确率更可控：先用 LLM 做推理式路由、再在小集合内精匹配，避免语义向量“相似但不对”“对但不相似”的召回误差。
- 路径可解释、过程可调优：每一层都是可观测的目录选择 + 追问策略，可迭代优化。
- 更贴合真实医疗组织方式：医疗资源本就是层次化结构（门诊—亚专科—医生），我们只是让 LLM 用“翻目录”的方式走一遍最合理路径。

我们的下一步目标是：在通用场景下自动构建可演进的层次化服务目录；本次比赛中，我们优先利用医疗领域先验完成目录搭建，验证这条技术路径在效率、稳定性与准确性上相对经典方案的优势，后续我们会搭建在通用场景下的自动层次化分类搭建维护方案，减少人工参与的同时，进一步提高常用服务的发现效率。
